# 家庭资源权限用户指南（V3.4）

HomeMaster 操作真实物品前必须先经过你的批准：精确到**哪一只物品 × 具体动作**，
以及**进入哪一个目的地区域**。本指南用“去卧室拿杯子”讲清完整流程。

## 一次真实流程

你说：“去卧室拿杯子。”

1. **导航先审批**。机器人移动前，申请卡出现：
   `进入卧室（○ 本次允许 ○ 始终允许 ○ 拒绝）`。
   选“始终允许”，以后进卧室不再打扰你；选“本次允许”，离开后再进还要再问。
2. **拿取后审批**。到达后，新的申请卡出现：
   `拿取白色杯子（卧室 · 床头柜）`。注意卡片只显示名称、位置和动作，
   从不显示内部编号——后台仍精确绑定这一只杯子，同名杯子不共享授权。
3. **执行与完成**。“已批准”和“执行完成”是两回事：
   前者是你点了提交，后者是机器人真的拿起了杯子。
   如果拿取被拒而导航已完成，页面会说“未拿取白色杯子，机器人当前在卧室”，
   不会说“整个任务零执行”。

## 三个选项的准确含义

- **本次允许**：只允许当前这一次。拿取成功（或调用结束）后即消耗；
  下次再拿同一只杯子会重新申请。
- **始终允许**：长期保存，跨重启、跨会话有效，直到你手动撤销。
  同一件的不同动作互不包含：允许拿取 ≠ 允许放置、清洗；
  允许杯 A ≠ 允许杯 B。
- **拒绝**：本次调用不执行。同一张卡上其他项的长期选择仍然保存；
  已经完成的步骤不会被回滚。

## 只查目的地，不管途经

区域权限只检查目的地。去卧室的路上经过客厅、厨房，不会逐个弹卡；
 entering 同一区域内停留不产生新申请；离开后再进入需要重新批准。

## 长期授权的查看与撤销

对话页左栏进入**权限**页：物品动作与目的地区域分两个页签，
同一物品的不同动作分开展示，可单独撤销（撤销拿取不影响放置）。
撤销后读回后端确认；刷新页面或新开浏览器，结果一致。
撤销只阻止未开始的步骤，已经开始的物理动作不承诺瞬间回滚。

## 各入口的行为差异

- **网页**：逐项卡片（本指南上述全部能力）；关闭卡片或 `Esc` 等于取消本次申请，
  不保存未提交的选择。
- **交互式 CLI**：逐项按 `1=本次允许、2=始终允许、3=拒绝` 回答；非法输入重问当前项，
  `EOF`/取消终止本次申请。
- **飞书**：本版不支持逐项交互卡片。涉及家庭资源权限的调用在飞书通道内直接报告
  “审批通道不可用”，物理调用不会启动；请到网页或 CLI 完成审批。

## 失败与重试

- 提交失败：保留你的选择，提示保存失败并允许重试，不显示“已批准”。
- 执行中遇到已确认的短暂失败（如设备忙），只在目标不变且预算允许时有限重试；
  重试次数与操作计数可在运行事件里看到。
- 超时、断线、服务重启会使悬挂申请 fail closed；长期授权不受影响；
  重启后未完成的申请标为中断，需要重新发起。

## 旧行为的变化

- 普通工具（读写文件、搜索等）不再有通用二次确认弹窗；原有非交互硬拒绝保留。
- 权限模式 `full_auto` 不能跳过家庭资源权限：物品动作与目的地区域永远先批后动。
- 历史工具审批不会迁移成长期规则；首次动作仍需你批准一次。
