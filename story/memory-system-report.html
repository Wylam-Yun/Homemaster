阶段建设汇报 · MEMORY LIFECYCLE

让每一次任务，成为下一次任务可复用、可纠错、可追溯的经验

本阶段不是新增一个“记事本”，而是把经验接入 Agent 的任务前、执行中和任务后，形成从沉淀、召回到纠错整理的 Memory 闭环。

会记 · 已完成显式保存 + Session 自动沉淀
会找 · 已完成基础版新任务前自动召回 + 主动搜索
会改 · 核心完成更新、删除、反馈、版本追溯
会进化 · 待建设从 Memory 晋升为标准 Skill
历史经验只作为决策参考，不能绕过当前权限、SOP和真实环境核验。
01 · Why

记忆改造要解决的，不只是“信息会丢”

蓝图中的核心业务矛盾是一条连锁反应：经验无法沉淀和更新，最终把重复理解、漏检风险和长期陪跑重新压回配合人。

问题 01

经验分散在个人和历史会话

成功做法、失败原因、检查依据缺少统一沉淀。

问题 02

相似任务每次重新理解

历史经验找不到，Agent和配合人都要重新探索。

问题 03

步骤多时容易漏检误判

过去踩过的坑不能自动提醒当前任务。

问题 04

错误经验缺少纠正和淘汰

SOP和环境变化后，旧经验可能持续误导。

问题 05

配合人重复检查、长期陪跑

精力消耗在历史查找、过程复核和材料整理上。

本阶段业务目标让经验能够自动沉淀、主动召回、进入决策、持续纠错，并且每次变化都有来源和验证。

技术名词速查

保留专业名称，同时说明它在当前系统中实际承担的职责。

MindMemOS记忆管理框架

提供记忆新增、检索、更新、删除、反馈与整理能力，是本次接入的核心记忆引擎。

Qdrant向量数据库

保存记忆正文和语义向量，支持按照“含义是否相关”召回历史经验，而不只是匹配关键词。

Neo4j图数据库 / 知识图谱存储

保存记忆的来源、关联和版本演进关系；当前已形成记忆知识图谱基础，尚不是完整业务知识图谱。

Embedding语义向量化

把文本转换成可计算的语义向量，使系统能够比较当前任务与历史经验的含义相似度。

Evidence记忆证据 / 数据来源

证明记忆来自哪次用户表达或真实执行结果，用于阻止无依据和跨任务写入。

Lineage数据血缘 / 版本链

记录记忆从旧版本到新版本的演变，使更新前后内容、来源和关系均可追溯。

FIFO Queue串行任务队列

让新增、任务后学习和后台整理按接收顺序执行，降低并发修改造成的数据冲突。

Dreaming记忆巩固与整理机制

在经验积累到阈值后，对固定批次执行去重、冲突处理和关联整理。

02 · When

六项能力不是一起调用，而是分布在任务生命周期中

调用时机决定了记忆是否可信、是否来得及影响决策，也决定了系统会不会频繁误改历史经验。

用户提交任务

Runtime登记当前用户陈述，形成当前任务可信来源。

证据建立

任务开始前

新Session或Compact后自动查找Top-3相关历史经验。

SEARCH

Agent决策

经验进入上下文，辅助规划、工具选择、检查和风险判断。

READ & USE

任务执行中

确认新事实时Add；发现历史变化时Update、Delete或Feedback。

ADD / UPDATE / DELETE

Session结束

Finalizer从真实轨迹提炼经验，并执行隐式Feedback。

AUTO ADD / FEEDBACK

经验累计后

默认每累计8条已确认新增，锁定批次进行Dreaming整理。

DREAMING
为什么Search放在第一次决策前？再晚一步，Agent可能已经按“没有历史经验”的前提完成了错误规划。
为什么Dreaming不在每次Add后执行？积累足够样本后再比较，才能减少频繁改写和单条经验造成的误判。
03 · Logic

每项功能都回答五个问题

点击功能查看：何时调用、为什么此时调用、数据怎么存、怎么取、取出后怎么进入Agent，以及对应的风险控制。

Add · 把可靠事实和成功经验变成长期资产

有两条入口：明确事实采用确定性直接写入；完整Session由结束处理器（Finalizer）自动提炼，分别服务“准确保存”和“从过程学习”。

调用时机用户或环境已经确认稳定事实/成功流程；或Session结束后系统发现可复用经验。
此时信息已有来源和结果，能够避免把猜测与临时状态写入长期库。

何时调用

任务执行中确认事实时显式调用；Session结束时系统自动触发经验提炼。

怎么存

正文和语义向量写入Qdrant；来源关系写入Neo4j知识图谱；任务状态进入FIFO串行队列审计。

怎么取

后台按记忆唯一ID精确回读，核对正文、类型和当前生效状态。

取后怎么用

下一次Search可召回，作为历史方法、事实和失败线索进入Agent上下文。

完成判据

工具返回“已接收”只代表进入队列；真实写入并回读后才代表持久化完成。

风险控制：Add必须使用当前用户陈述或真实环境观察；模型不能用旧任务证据（Evidence）为新记忆背书。

Search · 在Agent第一次决策前找回历史经验

自动召回负责提供初始Top-3线索，Agent主动搜索负责扩大范围、换词追查或获取精确memory ID。

调用时机新Session第一轮、Compact完成后的下一轮自动触发；任务中按需主动触发。
第一次决策前看到经验，才能从一开始影响规划；执行中再搜索用于补足自动召回覆盖不足。

何时调用

任务开始前自动Top-3；遇到相似历史、未知步骤或需要准确ID时主动搜索。

数据在哪

从Qdrant向量数据库读取语义相近的正文和候选ID，再核对原始记忆与类型。

怎么取

返回唯一ID、正文、类型、时间、相关度和来源；当前覆盖七种MindMemOS原生类型。

取后怎么用

自动召回结果进入记忆上下文；主动搜索结果进入下一轮模型请求。

影响什么

辅助规划、工具选择、检查项、异常判断；也为Update、Delete、History提供准确ID。

风险控制：历史经验被明确标记为参考信息，不是当前用户指令，也不会自动获得生产操作权限。

Update · 信息变化时精确修正，并保留版本链

当准确ID和完整新值都已明确，直接更新比让系统重新判断修改方式更稳妥。

调用时机已通过Search找到准确记忆ID，并已明确知道完整正确的新内容。
对象和新值都确定时才更新，可以减少误改其他相似记忆。

何时调用

业务事实、流程或适用范围已发生明确变化，需要替代原记忆时。

怎么存

结构化记忆新建版本并归档旧版；Vanilla记忆使用原生同ID更新。

怎么取

分别回读旧版、新版和完整记录，并核对Neo4j知识图谱中的版本演进关系。

取后怎么用

后续Search优先返回当前生效的新版本；History可以从任一版本追溯演变。

完成判据

旧版已归档、新版已生效、正文与完整记录一致，并且真实版本关系存在。

风险控制：结构化记录存在但已损坏时直接拒绝更新；不能只改显示正文而保留旧结构化值。

Delete · 让错误、重复和永久失效经验停止影响后续任务

Delete用于“这条信息不应继续生效”，普通信息变化应优先Update保留历史。

调用时机用户明确要求忘记，或记忆已确认完全错误、重复、永久失效。
只有删除语义已经明确时才淘汰，避免把“需要修正”误处理成“彻底删除”。

何时调用

准确目标已找到，并有明确忘记、错误、重复或永久失效判断。

怎么存

通过MindMemOS原生删除/归档路径改变状态，保留必要操作记录。

怎么取

按准确ID回读，确认目标不再处于可生效、可召回状态。

取后怎么用

后续Search不再把该条作为有效经验返回，停止污染Agent决策。

完成判据

数据库中的原始状态已经变化，而不是只收到“删除命令已发出”的日志。

风险控制：必须使用准确记忆ID并通过修改权限校验；不允许根据模糊描述批量猜测删除。

Feedback · 用户只需表达纠正，不必理解底层记忆操作

系统根据本轮真正可见的记忆判断应该新增、更新、删除还是保持不变；Session结束后还会执行隐式Feedback。

调用时机用户指出历史经验不准确，但正确动作还不能归结为“准确ID + 完整替代内容”。
先理解纠正的适用范围，再决定修改方式，避免过早删除或改错相似记忆。

何时调用

显式：用户自然纠正；隐式：Session结束后根据真实add/search操作记录触发。

怎么存

冻结该次成功模型请求实际看到的上下文、候选记忆和反馈处理结果。

怎么取

重新读取每个候选原始记忆，核对所属范围、生效状态、正文和来源。

取后怎么用

规划新增、更新、删除或保持不变；结构化更新必须提供完整替代内容。

完成判据

每项修改独立核对原始状态和版本链；任一失败不会包装成整体成功。

风险控制：Feedback只能处理该次成功模型请求真实看过的自动召回或手动搜索结果，不能修改任意ID。

Dreaming · 经验积累到一定规模后集中整理

它不是每次新增都执行，而是在同一项目和用户范围累计默认8条已确认新增后锁定固定批次，处理重复、冲突和关联。

调用时机Session结束处理完成后达到阈值，或系统启动时发现上次未完成批次。
足够样本才能进行比较；固定批次可以避免处理过程中目标不断变化。

何时调用

默认累计8条经真实回读确认已生效的普通新增记忆后自动触发。

怎么存

持久化batch ID、memory IDs、scope、pending状态和每个action结果。

怎么取

读取固定批次内每条原始记忆、来源、状态和已有版本关系。

取后怎么用

对重复、冲突、相关经验执行合并、更新、删除、建立关系或noop。

完成判据

所有整理动作的原始记录、版本关系和新增结果均验证通过后，才将该批次标记为完成。

风险控制：失败批次保留pending并重试；执行中新增经验留给下一批。当前Dreaming只整理Memory，不直接修改Skill。
04 · Store / Read / Use

存、取、用是三条不同的责任链

Agent判断是否需要记忆；Runtime校验当前用户、任务范围与证据；MindMemOS执行记忆管理；Qdrant向量数据库与Neo4j知识图谱提供可验证的真实结果。

写入链路 · 从事实到可检索经验

1
Agent提出Add / Update / Feedback只表达业务内容，不自行指定内部用户范围、任务标识或证据凭证。
↓
2
Runtime校验权限与当前证据确认来自当前用户陈述或真实环境观察。
↓
3
MindMemOS执行记忆修改显式Add进入FIFO串行队列；更新、删除和反馈同步确认结果。
↓
4
从两类数据库回读真实结果Qdrant核对正文与状态，Neo4j知识图谱核对来源与版本关系。

召回链路 · 从历史经验到当前决策

1
Runtime构造当前任务查询新Session使用用户问题；Compact后结合摘要、任务状态和当前消息。
↓
2
MindMemOS执行向量检索通过Qdrant找回语义最相关的3条经验，或按Agent要求扩大搜索。
↓
3
有效记忆进入模型真实请求自动召回进入记忆上下文；主动搜索作为工具结果进入下一轮。
↓
4
Agent参考经验重新决策用于规划、工具、核验和异常判断，但不替代当前环境验证。

Qdrant · 向量数据库

保存记忆正文、语义向量、类型和状态，承担相似度检索及记忆唯一ID回读。

Neo4j · 知识图谱存储

保存记忆来源、相互关联和版本演进关系，支撑知识关联、来源追踪和历史追溯。

文件与JSONL · 运行上下文与审计

保存用户上下文、证据、后台任务、任务后学习阶段和Dreaming批次状态。

05 · Engineering

不是“接入一个库”，而是重构六类记忆运行逻辑

8个近期提交被归并为6类逻辑变化：每一类都说明原有问题、系统改成什么、实际完成什么，以及最终解决的业务风险。

6

类逻辑改造

以业务运行逻辑为主线，8个Commit作为工程证据。目标是把MindMemOS从独立组件变成HomeMaster可控、可验证的经验系统。

01

底层引擎与双存储模型适配

MindMemOS · Qdrant · Neo4j
原有问题

MindMemOS是独立记忆组件，不理解HomeMaster的用户、项目、记忆类型和Agent调用方式；底层“能存”不等于业务“能正确使用”。

逻辑变化

建立HomeMaster与MindMemOS之间的适配层：统一身份范围和记忆类型，并明确内容检索与知识关系由不同存储承担。

完成工作

移除原Mem0运行路径；接入MindMemOS；将记忆正文与语义向量写入Qdrant，将来源、关联和版本关系写入Neo4j知识图谱。

解决问题

记忆能力从“独立组件存在”变成“Agent可按正确用户、项目和类型调用”，并具备语义检索与关系追溯两种基础能力。

技术证据0be12df
02

知识图谱服务生命周期治理

Neo4j · 多进程协调
原有问题

多个HomeMaster进程可能同时启动或停止同一个Neo4j服务，造成端口冲突、服务被误停，或者异常退出后残留错误占用状态。

逻辑变化

把Neo4j从“谁调用谁管理”改为“同节点多进程协同管理”：首个进程启动、最后一个进程退出时停止，并保护外部已存在服务。

完成工作

加入文件锁、租约登记、陈旧租约恢复、首末进程判断和外部服务识别，明确知识图谱服务的所有权与退出规则。

解决问题

降低多实例并发时的启动冲突、误停和不可恢复风险，使知识图谱服务能够稳定支撑长期记忆关系。

03

历史经验进入Agent第一次决策

自动召回 · 上下文注入
原有问题

系统即使保存了历史经验，如果Agent制定计划之后才查询，记忆也无法影响最关键的第一次判断，容易继续重复过去的错误。

逻辑变化

把检索时机前移到新Session第一轮以及上下文压缩后的下一轮，在规划开始前自动召回语义最相关的3条经验。

完成工作

构造当前任务查询，通过Qdrant向量检索获得候选记忆，并将有效结果注入该任务的第一次模型真实请求；执行中仍支持Agent主动搜索。

解决问题

记忆不再只是“可以查询的资料库”，而是在任务一开始就能辅助规划、工具选择、检查项和风险判断。

技术证据0742060
04

从真实任务过程自动提炼经验

Finalizer · 异步学习
原有问题

依赖用户手工总结会遗漏大量工具结果、失败过程和最终验证；如果结束学习同步执行，又会阻塞用户开始下一项任务。

逻辑变化

Session结束后由Finalizer从真实运行轨迹提炼经验；切换新任务时，旧任务学习进入后台串行队列，前台立即开始新Session。

完成工作

筛选用户、Agent与工具结果，转换成MindMemOS可学习输入；保存处理阶段以支持恢复；正常退出前等待已接收任务完成。

解决问题

成功方法和失败线索能够自动沉淀，不再依赖人工复盘；后台学习也不会占用下一项任务的交互时间。

05

从“会存会搜”扩展到“会纠错会整理”

Feedback · History · Dreaming
原有问题

只有新增和检索时，错误、重复或过期经验会长期存在；直接覆盖又会丢失历史，无法说明一条记忆为什么发生变化。

逻辑变化

把更新、删除、自然语言反馈、历史追溯和批量整理接入统一闭环；修改后保留版本演进关系，Dreaming按固定批次集中整理。

完成工作

实现显式与隐式Feedback、Update、History、版本状态、Neo4j版本链，以及可持久化、失败可重试的Dreaming批次。

解决问题

用户可以自然纠正历史经验；系统能够让错误内容停止生效、保留演变依据，并对重复和冲突经验进行持续治理。

06

建立可信证据边界与确定性写入

Evidence · FIFO · Embedding
原有问题

模型携带证据可能造成跨任务复用；并发写入可能互相冲突；明确事实若再交给模型解释，还会带来数分钟延迟、类型漂移和错误合并。

逻辑变化

证据由Runtime按当前用户、Session、任务和轮次选择；所有后台记忆写入统一串行；明确事实采用确定性直接写入，不再二次推理。

完成工作

移除模型传递内部证据凭证的能力；建立单FIFO队列；显式Add只执行Embedding、Qdrant写入、Neo4j来源关系建立和精确回读。

解决问题

降低旧证据支持新记忆、并发写坏数据和模型错误改写事实的风险，同时缩短明确事实的保存时间并稳定记忆类型。

06 · Safety

业务关心的不是“能不能记”，而是“会不会记错、改错、用错”

当前系统把成功标准放在外部真实数据，而不是模型说“我记住了”或日志显示“命令已发送”。

历史经验不等于操作授权

召回只能辅助判断，当前权限、SOP和环境终态仍需重新核验。

证据只属于当前任务

Runtime按当前用户、Session、任务和对话轮次绑定证据，旧任务证据不能支持新任务写入。

Feedback只能改本轮看过的记忆

目标必须来自本次成功模型请求真实看到的自动召回或手动搜索结果。

Update同时核对四类终态

正文、完整记录、新旧状态和Neo4j知识图谱版本关系缺一不可。

记忆写入固定串行

Add、Finalizer、Feedback和Dreaming共用单FIFO，避免并发改坏存储。

真实回读才算完成

Qdrant和Neo4j的外部终态是验收门，不能只依赖内部日志和模型回复。

08 · Outcome

本阶段解决了什么，下一阶段要补什么

当前交付定位是“经验自迭代底座和Memory核心闭环”，不是已经完成完全自主进化。

已经解决

  • 任务经验不再随着Session结束而消失
  • 相似任务开始前可以主动获得历史经验
  • 用户可以用自然语言纠正，而不必理解底层记忆修改方式
  • 错误、重复和过期经验可以更新、淘汰和整理
  • 每次变化有来源、有版本、有数据库终态验证
  • 后台学习不阻塞用户开始下一项任务

尚未达到

  • 运维专属经验结构、相似度和有效性规则
  • 历史经验与最新SOP、生产环境的自动一致性判断
  • 失败经验自动转成禁止、停止和回退约束
  • 连续失败后的降权、失效和淘汰标准
  • Memory自动晋升Skill及Draft、Diff、Rollback
  • 新旧Skill效果评测和人工发布Gate
阶段结论

已经从“保存信息”升级为“自动沉淀、主动召回、进入决策、持续纠错和版本追溯”；下一阶段从Memory闭环进入运维规则化与Skill Evolution。
