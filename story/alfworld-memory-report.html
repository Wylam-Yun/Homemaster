02 · 记忆系统

Memory 不是记事本，而是一套经验闭环

从保存、检索到纠错和长期整理，每一步都有明确作用。点击下面的能力查看它解决的问题。

Add · 把一次任务变成以后可复用的经验

Agent 可以显式保存事实或步骤；Session 结束时，Finalizer 也会从真实对话和工具结果中提取经验。保存后会读取实际存储结果确认成功，而不是只相信一条“已写入”日志。

历史经验告诉 Agent 过去发生过什么、过去怎样完成任务

04 · 权限系统

Memory 提供建议，Permission 决定能不能执行

所有工具调用共用同一道执行门。权限确认发生在资源申请和后端执行之前，拒绝或超时不会触发真实操作。

STEP 1

Agent 提出操作

例如写文件、启动进程，或调用会改变环境状态的工具。

STEP 2 · SINGLE GATE

参数校验与权限判断

先校验真实参数，再根据身份、能力、路径和模式做出决定。

允许人工确认拒绝
→
STEP 3

执行或停止

批准后才调用后端；拒绝、超时、取消和连接中断都按拒绝处理。

full_auto自动执行，适合 benchmark 和受控自动化。
confirm修改性操作等待人工批准后继续。
plan允许分析和规划，阻止实际修改。
CLI 确认Web 审批框飞书审批卡片共用同一权限策略与执行器
05 · Web Console

把 Agent 的过程呈现给用户

Web Console 不另建一套 Agent，而是把同一个 Application Runtime 的实时事件、安全工具结果和审批请求投影到浏览器。

06 · 阶段结论

从“能执行”走向“会积累、可控制、可观察”

这三项能力共享同一个 Runtime，Memory 不扩权，Permission 不复制业务逻辑，Web Console 不创造第二个执行终态。
